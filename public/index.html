1. Pengujian Load Balancing (Distribusi Trafik)

Kubernetes Service bertipe NodePort mendistribusikan trafik secara merata ke Pod-pod yang aktif di cluster secara round-robin.

# Uji load balancing di browser:
1. Klik tombol "Dapatkan Kutipan Baru" berulang kali.
2. Perhatikan indikator "Dilayani oleh Pod: [NAMA_POD]" di bagian footer.
3. Jika replica diset 2, maka nama Pod pengirim akan bergantian secara dinamis antara Pod A dan Pod B.

2. Pengujian Autoscaling (HPA)

Membuktikan kemampuan Kubernetes untuk menambah pod secara elastis ketika server mendapat beban trafik tinggi.

# Langkah memicu autoscaling:
1. Buka Terminal Baru di PC Anda dan jalankan perintah:
kubectl get hpa mindful-hpa -w
2. Pada dashboard web, klik tombol merah "Simulasikan Trafik Ujian" 2-3 kali.
3. Perhatikan lonjakan CPU di panel metrik web (naik ke 98%) dan di terminal Anda.
4. Setelah penggunaan CPU rata-rata melampaui target limit 50%, HPA akan men-scale jumlah replika Pod dari 2 menjadi 3, 4, hingga 5 Pod secara otomatis.

3. Pengujian Liveness Probe (Self-Healing)

Liveness Probe memantau kesehatan server di `/health` setiap 10 detik. Jika endpoint ini mengembalikan status gagal, K8s akan otomatis menghancurkan kontainer lama dan membangun kontainer baru.

Berikut adalah penjelasan terstruktur mengenai output log yang muncul saat Anda menjalankan server di terminal. Informasi ini sangat berguna untuk menjelaskan cara kerja sistem backend stateless Anda selama presentasi.

A. Banner Inisialisasi & Identitas Node

Saat perintah node server.js dijalankan, server akan menggambar logo ASCII **MindfulSpace** dan menampilkan status operasional. Logo ini mempermudah identifikasi tugas mahasiswa saat pengumpulan.

B. Status Environment & Pod Hostname

Variabel Pod Hostname mengambil data langsung dari process.env.HOSTNAME. Di lingkungan lokal komputer Anda, ini akan memunculkan nama PC Anda (misalnya `DESKTOP-3UB4F69`). Di dalam kluster Minikube, nilainya akan otomatis berisi **Nama Pod K8s** yang unik. Ini membuktikan bahwa aplikasi Anda bersifat **Stateless** dan terintegrasi dengan runtime Kubernetes.

C. Pemetaan Route API & Kegunaan K8s

  • GET / (Stateless Front-end): Melayani file HTML statis. Aplikasi tidak menyimpan session di server, sehingga bebas dipindah-pindah antar-pod.
  • GET /health (Liveness Check): Digunakan oleh K8s kubelet untuk memantau status pod sehat. Jika crash, pod di-restart otomatis.
  • GET /api/quote (Load Balancing Test): Mengirim JSON afirmasi akademik beserta nama pod yang melayani request ke browser.
  • GET /stress (Autoscaling Test): Memicu perulangan matematika super berat `Math.sqrt` 80.000.000 kali untuk memanaskan CPU agar HPA mendeteksi lonjakan di atas 50% dan melipatgandakan Pod.
